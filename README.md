# 测评授权码系统

所有测评 HTML 的统一门禁。**一个壳页接管全部测评**：用户拿授权码进来 → 服务端校验 → 通过才放行到对应测评页 → 首次使用即核销，转发给别人会提示「已被使用」。

零 npm 依赖（只用 Node 内置模块），不需要 `npm install`，断网可跑。

---

## 一、启动

**双击 `一键启动.command`**（macOS）。首次运行如提示「无法打开，因为无法验证开发者」，右键 → 打开，或在终端执行一次：

```bash
chmod +x 一键启动.command
```

启动后终端会打印：

```
入口页  http://localhost:8787/
管理页  http://localhost:8787/admin  （密码登录；公网同一入口）
```

浏览器会自动打开管理后台。管理后台**公网可访问，但要密码登录**；密码写在 `server.js` 的 `ADMIN_PASSWORD` 常量（默认 `jy120218`，可用环境变量覆盖），登录后 7 天内免重复输入，连续输错 8 次锁定 10 分钟。

其它方式：

```bash
node server.js                # 或 ./start.sh
PORT=9000 node server.js      # 换端口
```

## 二、三个页面

| 地址 | 用途 |
|---|---|
| `/` | **壳页**。用户输入授权码 → 选测试 → 跳转。这也是自动发货要发的链接落地页 |
| `/admin` | 管理后台（**密码登录**，公网同一入口）。生成码、按通用/各测评分类看列表、作废、复制 |
| `/tests/<id>.html` | 测评页本体。**没有有效 Cookie 打不开**，会被弹回壳页 |

**自动发货用的两种链接形式**（手动模式 / 理解原理时用）：

```
http://你的域名/go?code=LA-A3K9-QM4X&test=lianai      # 推荐，短、可读
http://你的域名/tests/lianai.html?c=LA-A3K9-QM4X      # 直达，效果相同
```

> 推荐用**接口发货**：让发货工具下单后调 `POST /api/issue` 现场生成码并直接拿到上面的兑换直链，无需手工备码池。详见第五节。

## 三、接入一个新的测评（3 步）

1. 把测评 HTML 放进 `public/tests/`，文件名用英文，如 `xinli.html`；
2. 在 `config/tests.json` 里登记：

```json
{ "id": "xinli", "name": "心理年龄", "subtitle": "你的心理年龄是几岁？",
  "file": "xinli.html", "price": 1.99, "status": "online" }
```

3. 在测评页 `</body>` 前加**一行**：

```html
<script src="/gate-client.js"></script>
```

加完之后：用户必须从壳页或带码链接进来；页面右下角会出现半透明水印（授权码尾号 + 你生成的备注），截图可溯源。

> **写新测评页时注意手机端两件事**（已在 `lianai.html` 里做过，照抄即可）：
> 1. **不要把 `:hover` 写在顶层的**，要包进 `@media (hover: hover) { ... }`。手机浏览器有「sticky hover」：会把最后一次点击的位置一直保持在 hover 状态，题目/选项切换时新元素正好渲染在同一坐标上，就会出现「一进这题某个选项已经是淡紫色」的现象。
> 2. 加 `* { -webkit-tap-highlight-color: transparent; }`，否则安卓点按会闪一块半透明高亮。
>
> 另外 `gate-client.js` 判断「有没有门禁」看的是 `gate_display` Cookie（**不是** `gate_token`）——因为 `gate_token` 是 `HttpOnly` 的、JS 根本读不到，用它判断会导致从授权页自动跳进来时误弹「请从授权码入口进入」。

> `status` 填 `offline` 时该测试不出现在壳页里，码也验不过——用来做「准备好但还没上架」的品。

## 四、授权码规则

- 格式 `前缀-XXXX-XXXX`，字符集剔除了 `0 O 1 I L 2 Z 5 S B` 这类容易看错的字符；
- **默认一次性**（`maxUses=1`）：第一个打开的人用掉，第二个打开提示「已被使用」；
- `maxUses=0` 表示不限次数，只用于自己测试，别发给买家；
- `testId` 填 `*` 是通用码，用户进壳页后自己选测试；填具体 id 则锁定只能进那一个；
- **同一个浏览器重复进入不扣次数**：码用完后，买家按返回键回到授权页、或再点一次同一条兑换链接，都会自动放行重新进入；转发给别人仍然会被拦（对方没有这台浏览器的 Cookie）；
- `备注` 会显示成水印，建议填买家昵称或订单号，维权时是证据。

## 五、API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/verify` | `{code, test}` 校验，通过则下发签名 Cookie |
| GET | `/api/config` | 壳页用：已上架测试列表 |
| POST | `/api/admin/login` | **管理登录**，body `{password}`，通过则下发会话 Cookie（7 天） |
| POST | `/api/admin/logout` | 退出登录（清会话 Cookie） |
| POST | `/api/admin/generate` | 批量生成（**需登录**），body `{prefix,count,testId,maxUses,note}` |
| GET | `/api/admin/list` | 全部码 + 统计（**需登录**） |
| POST | `/api/admin/revoke` | 作废单个码（**需登录**） |
| GET | `/api/admin/tests` | 全部测试（含未上架，**需登录**） |
| POST | `/api/issue` | **下单后现场生成码**（接口发货用），body `{testId,note,maxUses}`，返回 `{code, redeemUrl}` |
| GET | `/healthz` | 健康检查 |

**管理后台（`/admin` 及 `/api/admin/*`）需要密码登录**：`/admin` 页面本身公开（只是登录框），`/api/admin/list` 等数据接口没有有效会话一律返回 401。密码是 `server.js` 里的 `ADMIN_PASSWORD` 常量（默认 `jy120218`），登录成功签发 HMAC 签名 Cookie（`admin_session`，HttpOnly，7 天）；签名密钥由该密码派生，**改密码即让所有旧会话立即失效**，也不依赖 `data/` 目录（重新部署后照样能登录）。

`/api/issue` 鉴权：请求头 `x-issue-token` 必须等于环境变量 `ISSUE_TOKEN` 的值。未设置 `ISSUE_TOKEN` 时，公网签发被锁定（返回 401），避免谁都能刷码；**本机直连免令牌**。公网部署请务必设置 `ISSUE_TOKEN`。

### 推荐：下单后现场生成（接口发货，零库存）

不用预生成码池，也不会「码不够发不出货」。把自动发货工具（阿奇索等）配成**接口发货**模式，让它每笔订单付款后调用：

```http
POST https://你的域名/api/issue
Content-Type: application/json
x-issue-token: 你的签发令牌

{ "testId": "lianai", "note": "订单号SH20261015-001" }
```

返回：

```json
{ "ok": true, "testId": "lianai", "count": 1,
  "codes": [ { "code": "LIAN-R6JJ-MHY7",
               "redeemUrl": "https://你的域名/tests/lianai.html?c=LIAN-R6JJ-MHY7" } ] }
```

把 `redeemUrl` 当成发货内容发出去即可——买家点一下直接进测试（零输入）。`testId` 固定填该商品对应的测试 id（见 `config/tests.json`）。通用码用 `testId: "*"`，此时返回 `/go?code=...&test=*` 短链（壳页自选测试）。

> 仍想用「卡密池」模式也行：在 `/admin` 批量生成 → 复制 → 导入发货工具的卡密库。但 JIT 接口发货免库存、更省心，新项目建议直接用。

## 六、数据文件

| 文件 | 内容 | 能删吗 |
|---|---|---|
| `data/codes.json` | 授权码库 | 删了等于清空所有码 |
| `data/secret.key` | Cookie 签名密钥 | 删了全部已发 Cookie 失效，用户要重新验证 |
| `config/tests.json` | 测试注册表 | 改它就是上下架 |

想清空重来：停服务 → 删 `data/codes.json` → 启动。

### 关键：码存在哪、会不会丢

授权码全部存在一个 JSON 文件里：`DATA_DIR/codes.json`（默认 `<项目目录>/data/codes.json`），格式是 `{ "授权码": {…} }`。每条形如：

```json
"LA-668M-XYBG": {
  "code": "LA-668M-XYBG", "testId": "lianai", "prefix": "LA",
  "maxUses": 1, "usedCount": 1, "note": "", "createdAt": "...",
  "firstUsedAt": "...", "lastUsedAt": "...", "revoked": false
}
```

**但"存在哪"要分两种情况，而且是两套互不相通的码库：**

| | 本机跑（`node server.js`） | 线上跑（发布后的公网链接） |
|---|---|---|
| 码库位置 | `/Users/baihuifang/AI测试网页/测评授权码系统/data/codes.json` | 平台沙箱容器里的 `data/codes.json`（运行时新建） |
| 你现在有多少码 | `{}`（空的） | 见 `/admin` 后台 |
| 会同步吗 | **不会**，两边完全独立 | 同上 |

> ⚠️ **`data/` 被 `.gitignore` 忽略，所以它不随部署上传** —— 线上码库不是"你本地文件的副本"，而是沙箱自己从零开始的。

### 重新部署会发生什么（重要）

**每次重新部署，线上码库会清零，之前生成的码全部失效，使用数据也一并丢失。** 具体三件事：

1. 所有已生成的码变成"不存在"（买家再来用会提示授权码不存在）；
2. 使用记录（`usedCount` / `firstUsedAt` / `lastUsedAt`）全丢 —— 售后维权时要的"这码什么时候被谁用过"的证据也没了；
3. `data/secret.key` 一起重生 → **已经发出去、正在有效期内的买家 Cookie 全部失效**，正在做题的人会被打回授权页。

这不是 bug，是这套部署方式的设计限制：`data/` 不上传，沙箱每次重建都是全新容器。**链接本身不会失效（见文末附录），失效的是数据。**

### 因此，运营上这样做

- **要用的码都在线上生成**（`/admin` 或 `/api/issue`），本地生成的码不会出现在线上；
- **重新部署前先备份码库**：登录 `/admin` → 复制列表；或者用下面这条命令导出成本地文件（会存到 `data/backup/`，该目录同样被 gitignore、不会进仓库）：

```bash
curl -s -b <登录后的cookie> https://ceping-gate.app.workbuddy.host/api/admin/list > codes-backup.json
```

- 想彻底不再担心，按 `部署SOP.md` 第 7 节迁到自有服务器 —— 数据落在你自己硬盘上，重启、重部署都不丢。

## 七、部署到公网

> 完整的部署流程、环境变量、验收清单与踩坑记录见 **[部署SOP.md](./部署SOP.md)**；令牌等敏感值备份在 `data/deploy.env`（该目录不上传、不进仓库）。

**当前部署**：已发布在 **https://ceping-gate.app.workbuddy.host/**（WorkBuddy 发布应用，服务端+前端同一个链接）。该环境靠启动命令注入两个环境变量：

```bash
ISSUE_TOKEN=<签发令牌> PUBLIC_URL=https://ceping-gate.app.workbuddy.host node server.js
```

- `ISSUE_TOKEN`：公网自动发货令牌（不设则 `/api/issue` 在公网被锁死）
- `PUBLIC_URL`：对外域名。反向代理不透传原始 Host 时，`/api/issue` 返回的兑换短链会退回内部域名，用它固定为公网域名
- 管理后台用密码登录，公网同一入口 `/admin`，不需要额外配置
- ⚠️ **每次重新部署会重置云端码库**（`data/` 目录不上传），线上生成的授权码会丢；上线后不要随手重部署

**授权码校验必须在服务端做**，所以 Netlify Drop / 纯静态托管做不了（页面能被直接扒走）。三条路：

1. **验证期最快——本地服务 + 内网穿透**，5 分钟出公网 HTTPS 链接：
   ```bash
   node server.js
   ngrok http 8787          # 或：cloudflared tunnel --url http://localhost:8787
   ```
   把生成的 `https://xxx.ngrok.io` 填进阿奇索的链接里即可。免费版域名每次重启会变，适合测流程。
2. **长期主力——一台 VPS**（腾讯云/阿里云轻量，约 40-100 元/月）：
   ```bash
   node server.js &                    # 或装 pm2 守护
   # 再用 nginx 反代到 8787，绑域名 + HTTPS 证书
   ```
3. **想继续用 Vercel**：把 `server.js` 的路由改写成 Vercel Serverless Functions（`api/*.js`），存储换成 Vercel KV 或任意云数据库。页面本身不用改。

## 八、常见问题

**忘记管理密码 / 想换密码？` 改 `server.js` 顶部的 `ADMIN_PASSWORD` 常量（或设环境变量 `ADMIN_PASSWORD`）后重启即可，改完所有旧的登录会话立即失效。连续输错 8 次会锁 10 分钟。

**登录后过段时间又要重输密码？` 会话有效期 7 天；改过密码或清过浏览器 Cookie 就需要重新登录。若仍要重置发货签发令牌，改 `ISSUE_TOKEN` 环境变量值并重启即可。

**想改端口？` `PORT=9000 node server.js`。

**买家说「已被使用」但他第一次打开？` 先看 `/admin` 里这个码的状态和首次使用时间。常见原因是链接被平台或群聊预加载扫过（微信/QQ 会提前抓取链接），这种情况把 `maxUses` 调到 2-3，或改用壳页链接 `/go?code=...`（不会被预抓）。

**买家按了返回键，再进来提示「已被使用」？` 已经不会了。系统会认「是这台浏览器用了这张码」：按返回键回到授权页、或重复点开同一条兑换链接，都会自动放行且不扣次数。真正被拦的只有换设备/换浏览器打开——那是转发。另外授权页跳进测评页时用的是 `location.replace`，授权页不留在浏览历史里，正常按返回会直接离开，不会再回到授权页。

**通用码的兑换链接打开后报「测试不存在」？` 已修复。通用码发的 `/go?code=...&test=*` 短链以前会把 `*` 当成测试 id 去校验而报错，现在 `test=*` 会正确进入「选测试」页面，由用户自己挑要进哪个测。

**测评页直接改本地 JS 能绕过吗？` 不能。`/tests/*` 由服务端挡着，删掉页面里的 `gate-client.js` 只是没了水印，页面照样打不开。

**在微信里点链接打不开，显示「请在浏览器中打开」？` 这是**发布平台的入口层策略，不是本项目的代码问题**：请求头带 `MicroMessenger`（微信、企业微信）会被平台直接返回 403，请求到不了我们的服务。实测 QQ / 支付宝 / 抖音 / 小红书 / 微博 / 钉钉 / Safari / Chrome 全部正常，只有微信系被拦，且判定只看 UA 关键字。

应对：① 临时 —— 引导买家在微信里点右上角 `···` → 在浏览器打开（平台的 403 页面自带「复制链接」按钮）；② 根治 —— 换到自己的域名部署，微信即可正常打开。详见 `部署SOP.md` 第 8 节。

**手机上刚进题目，某个选项就是淡紫色（像已经选中了）？` 已修复。原因是手机浏览器的 `:hover` 会「粘」在最后一次点到的地方，切题后新选项渲染在同一坐标上就带着 hover 底色。现在所有 hover 效果都包在 `@media (hover: hover)` 里，只在鼠标设备生效；同时加了 `-webkit-tap-highlight-color: transparent` 去掉点按高亮块。选项真正的选中态由 `[aria-checked="true"]` 控制，不受影响。

**手机上从授权页自动跳进测评页，顶部弹出「请从授权码入口进入」？` 已修复。门禁 Cookie 有两个：`gate_token`（`HttpOnly`，服务端校验用，JS 读不到）和 `gate_display`（可读，存尾号/备注）。旧的 `gate-client.js` 用 `gate_token` 判断「是否已授权」，而 JS 永远读不到它——所以从授权页跳进来（URL 上没带 `?c=`）时被误判为「没走授权入口」。现在改看 `gate_display`。顺带修了水印里中文备注乱码的问题（`atob` 出来是 Latin-1，要再按 UTF-8 还原一次）。

## 九、发给买家的话术（微信里打不开时）

因为发布域名在微信内会被平台拦（见上一节），**只要渠道是微信，发货时就要附一句引导**，否则买家会卡在「请在浏览器中打开」那一页。平台那页本身带了「复制链接」按钮，所以话术不用长。

**发货时（推荐，微信/QQ 私聊都通用）**

> 你的授权码：`LIAN-XXXX-XXXX`
> 打开方式：**把下面的链接复制到手机浏览器（Safari / Chrome）打开**；如果在微信里直接点了，请点右上角 `···` → 「在浏览器打开」。
> 链接：https://ceping-gate.app.workbuddy.host/

**买家问「怎么打不开，显示请在浏览器中打开」**

> 微信不让第三方网页在它的内置浏览器里打开，不是链接坏了哈～
> 麻烦你在微信里长按上面那条消息 →「复制」，然后打开手机浏览器（iPhone 是 Safari，安卓是 Chrome/自带浏览器），粘贴到地址栏回车即可；或者点右上角 `···` 选「在浏览器打开」。

**售后答疑**

| 买家说 | 你回 |
|---|---|
| 「提示该授权码已被使用」 | 该码仅限一次、且只能同一台设备重复进入；如果换过手机/浏览器，请提供订单号重新发码 |
| 「打不开链接」 | 见上面第二条话术 |
| 「做完没保存/退出去了」 | 测评进度存在本机浏览器里，用同一台设备、同一个浏览器再打开链接可继续 |

> 一条经验：**发货消息里把"复制到浏览器打开"放在最前面**（而不是等买家来问），能明显减少来回沟通。若哪天要正式放量卖，优先换自有域名——见 `部署SOP.md` 第 7、8 节。
